## Objective

`aggregate-dashboard.sh --repo` takes 37 seconds on this repo (measured
2026-08-26: 10.2s user, 20.3s system, 82% CPU). Twenty seconds of system
time on a read-only aggregation is fork overhead: the shape of a script
spawning `jq`, `yq`, `git` or `date` per row over a cost log thousands of
lines long, rather than once per file. Every consumer pays it: the TUI
polls this every 5 seconds (card 73 stops the freeze but the data still
arrives 37 seconds stale), both tickers re-run it per refresh by design,
and the HTML dashboard regenerates it per tick.

Profile first, then fix the shape: single-pass `jq`/`yq` invocations over
whole files, loops in awk or a single jq program rather than bash
while-read with per-row subprocesses, and one `date` call per run, not
per row. The envelope names the actual hot spots found, with their
before and after timings.

## Deliverables

1. **`--repo` completes in under one second** on this repo's real state
   (thousands of cost-log rows, fifty-plus stages), and the full fleet
   walk completes in under one second per subscriber.
2. **Byte-identical output.** Against pinned fixture inputs, the payload
   before and after the change diffs empty once volatile fields
   (`generated_at`, any timestamp derived from now) are normalised. Every
   consumer -- TUI, both tickers, HTML dashboard -- is a reason this
   contract exists; none of them changes.
3. **A performance guard in the smoke.** A fixture cost log of at least
   five thousand rows, generated by the smoke, must aggregate within a
   bound that fails the pre-fix shape and passes the fixed one with
   generous margin (the bound guards the shape, not the machine: choose
   it so a per-row-fork implementation cannot pass on plausible
   hardware, say ten seconds, while the fixed shape passes in well under
   one).
4. **The profile in the envelope**: the top time sinks found, each with
   its mechanism (per-row fork, repeated file parse, redundant git call)
   and its share of the 37 seconds, so the next person tuning this
   script inherits the map.

## Constraints

- Bash, jq, yq, awk, git: the existing toolset. No new dependency, no
  rewrite into Python.
- Output shape and field semantics are frozen. This card buys speed only.
- No caching layer, no daemon, no background refresh: the script stays a
  pure function of the files it reads. Speed comes from doing the same
  reads well.
- Existing smokes that consume the aggregate pass unmodified.

## Acceptance criteria

1. `time aggregate-dashboard.sh --repo <this repo>` under one second,
   shown against the real state on the worker's machine, alongside the
   pre-fix timing for the same invocation.
2. Byte-identical payloads on pinned fixtures, volatile fields
   normalised, shown as an empty diff. The fixture set covers a repo
   with agents live, a halted repo, marked zero-output rows, and the
   run scoping card 72 added.
3. The five-thousand-row performance guard passes on the fixed tree and
   fails on the pre-fix tree.
4. All existing consumer smokes pass unmodified: repo ticker, fleet
   ticker, TUI, TUI history, dashboard aggregation.
5. The envelope carries the profile per deliverable 4.
6. The smoke passes with locale and TERM pinned and its helpers fail
   loudly on anything absent.

## Contract test

On pinned fixtures spanning live agents, a halt, marked rows and run
scoping: the pre and post payloads diff empty after normalising volatile
fields; the five-thousand-row fixture aggregates inside the guard bound;
the real-repo timing lands under one second against a recorded pre-fix
baseline.
